## 2. Detailed Fix Log

### FIX-01: Genuine Google ADK Runtime Execution
- **File(s) Modified**: `backend/app/agents/perspective.py`, `backend/app/agents/conflict.py`, `backend/app/agents/resolution.py`, `backend/app/workflows/alignment.py`
- **Issue**: Google ADK `Agent` and `Workflow` instances were created in code, but runtime calls bypassed ADK's execution engine by invoking `self.client.models.generate_content(...)` directly.
- **Repair**:
  - Integrated `google.adk.runners.Runner` and `google.adk.sessions.InMemorySessionService`.
  - When live Gemini execution is active and `settings.use_adk_runner=True`, prompts are dispatched as `types.Content` to `runner.run_async()`, executing agent turns through the native Google ADK event-driven pipeline and updating session state.
  - Added explicit `execution_mode` metadata (`"LIVE_GEMINI"` vs `"MOCK_DETERMINISTIC"`), guaranteeing that simulated responses are never mislabeled as live Gemini inferences.

### FIX-02: Generalization for Arbitrary Participants
- **File(s) Modified**: `backend/app/agents/perspective.py`, `backend/app/agents/conflict.py`, `backend/app/agents/resolution.py`
- **Issue**: The mock fallback logic was hardcoded specifically for the names `Alex`, `Sam`, and `Taylor`. Input from any other team members was ignored, and conflicts between arbitrary teammates went undetected.
- **Repair**:
  - Replaced hardcoded member lookups with a dynamic entity and relation analysis engine.
  - Days of the week (`Monday` through `Sunday`) and milestone types are dynamically ranked and compared across all teammate pairs `(p1, p2)`.
  - Contradictory deadline inversions (e.g., launch scheduled before prerequisite completion) are automatically detected for any names (tested with `Elena`, `Marcus`, and `Priya`).
  - Genuine submitted statements are quoted verbatim in `source_quote` and `evidence` fields.

### FIX-03: Persistent Storage (Survives Application Restarts)
- **File(s) Modified**: `backend/app/services/supabase.py`, `backend/app/config.py`, `backend/migrations/001_initial_schema.sql`
- **Issue**: The previous storage service maintained state solely in ephemeral Python dictionaries (`self._projects = {}`), causing complete data loss whenever the server restarted.
- **Repair**:
  - Created version-controlled SQL DDL in `backend/migrations/001_initial_schema.sql`.
  - Implemented `aiosqlite` persistent storage in `backend/app/services/supabase.py` targeting `data/mediator.db`.
  - Migrations are verified and applied automatically upon startup.
  - Added environment-driven backend selection via `STORAGE_BACKEND`:
    - `"sqlite"`: Persistent local file storage (default).
    - `"supabase"`: Remote Supabase PostgreSQL integration.
    - `"memory"`: Ephemeral in-memory store for isolated unit tests.
  - Tested that data created in one storage instance survives restart and is fully loaded by a subsequent storage instance.

### FIX-04: Strict Decision Validation & Governance
- **File(s) Modified**: `backend/app/services/supabase.py`, `backend/app/routes/decisions.py`
- **Issue**: `POST /api/projects/{id}/decisions` allowed recording decisions for arbitrary string IDs that were never generated by the multi-agent workflow.
- **Repair**:
  - Added validation requiring `action.resolution_id` to exist in the project's latest `SynthesisReport`. If an invalid resolution ID is supplied, the API returns `HTTP 400 Bad Request` listing valid resolution IDs.
  - Action `MODIFY` now strictly requires non-empty custom `decision_text`.
  - Preserved governance rule: resolutions cannot be approved without explicit human team sign-off.

### FIX-05: Input Sanitization & Duplicate Member Prevention
- **File(s) Modified**: `backend/app/models/schemas.py`, `backend/app/routes/projects.py`, `backend/app/services/supabase.py`
- **Issue**: Empty strings and whitespace-only values were accepted for project titles, member names, and responses. Duplicate member names were permitted in the same project.
- **Repair**:
  - Added Pydantic `@field_validator` on `ProjectCreate.title`, `TeamMemberCreate.name`, and `MemberResponseSubmit.raw_text`, stripping whitespace and rejecting blank strings with `HTTP 422 Unprocessable Entity`.
  - Added duplicate member check in `add_team_member()`, raising `ValueError` and returning `HTTP 409 Conflict` if a member with that name already exists in the project.

### FIX-06: Global Exception Handling & Error Envelopes
- **File(s) Modified**: `backend/app/main.py`, `backend/app/models/schemas.py`
- **Issue**: Uncaught server exceptions returned unstructured 500 HTML/text pages.
- **Repair**:
  - Added `APIErrorResponse` schema and `@app.exception_handler(Exception)` returning structured JSON error envelopes:
    ```json
    {
      "error": "ValueError",
      "detail": "Descriptive message",
      "status_code": 500,
      "timestamp": "2026-10-10T19:40:00Z"
    }
    ```

### FIX-07: Minimal Dummy Frontend Test Harness
- **File(s) Created**: `backend/dummy_frontend/index.html`
- **File(s) Modified**: `backend/app/main.py`
- **Issue**: No lightweight UI existed to manually test the API flow before connecting Figma Make.
- **Repair**:
  - Created a single-page HTML/CSS/JS test harness in `backend/dummy_frontend/index.html`.
  - Served directly from FastAPI at `GET /test-ui`.
  - Supports: Backend connection ping, Create Project, Add Member, Submit Perspective, 1-Click Sample Trio loading, Run Multi-Agent Analysis, Formatted Conflict/Proposal cards, Decision sign-off, and Raw JSON viewer.
